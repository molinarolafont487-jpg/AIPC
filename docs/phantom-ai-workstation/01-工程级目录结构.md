# Phantom AI Workstation 工程级目录结构

## 1. 仓库策略

推荐使用一个 Monorepo 管理 MVP：

```text

│   ├── api/                         # FastAPI 后端，MVP 阶段为模块化单体
```

### 前端页面验收边界

| 页面 | MVP 必备能力 |
| --- | --- |
| 首页驾驶舱 | 今日任务、Agent 状态、知识库统计、系统建议、最近输出 |
| AI员工 | Agent 列表、详情、启停、权限、运行记录 |
| 知识库 | 文件上传、解析状态、文档列表、引用片段预览 |
| 任务中心 | 创建任务、状态流转、Agent 执行时间线、人工确认 |
| 会议中心 | 上传音频/纪要、生成摘要、拆任务 |
| 代码工厂 | 输入需求、生成 PRD/技术拆解/代码草案 artifact |
| 招投标中心 | 上传招标文件、提取评分点、生成响应表与风险 |
| 模型中心 | 本地/云端模型配置、路由策略、健康检查 |
| 设置 | 用户、角色、工作区、审计、存储、API Key |

## 6. Docker Compose MVP 拓扑

```text
services:
  web:
    app: Next.js
    port: 3000

  api:
    app: FastAPI
    port: 8000

  worker:
    app: Celery/RQ worker

  postgres:
    db: phantom
    extensions: pgvector 可选

  redis:
    usage: queue/cache/event

  qdrant:
    usage: vector database

  minio:
    usage: file and artifact object storage

  ollama:
    usage: local model runtime
    port: 11434
```

每个 PR 必须包含：

- 对应任务编号

- 截图或接口响应样例
- 测试说明

## 10. MVP 到生产拆分路径

MVP 阶段：

```text
FastAPI 模块化单体 + Worker
```

企业部署阶段可拆：

```text
auth-service
file-service
rag-service
agent-service
workflow-service
model-router
task-service
audit-service
```

拆分触发条件：

- 单模块 CPU/IO 占用长期高于 60%
- 任务队列积压超过 5 分钟
- 文件解析、Embedding、Agent 执行互相影响
- 企业客户要求独立审计或独立扩缩容
