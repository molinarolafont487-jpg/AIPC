## 1. 执行原则

```text
7天只验证一条主线
每天必须有可演示增量
先跑通黄金Demo，再补边缘能力
先用固定Demo数据保证稳定，再增强泛化能力
所有任务必须能映射到最终闭环
```

最终闭环：

```text
老板一句话
-> 任务卡
-> 数字员工分配
-> 飞书通知真人员工
-> 真人回复回流
-> AI继续执行
-> 老板助理汇总
-> 老板确认
-> 任务归档
```

## 2. 团队角色

| 角色 | 职责 |
| --- | --- |
| 产品/架构 | 规格、流程、验收、范围控制 |
| 前端 | Workbench页面、任务状态、协同消息 |
| 后端 | API、数据库、认证、任务流、飞书回调 |
| AI/RAG | Command Protocol、Prompt、知识库检索、Agent执行 |
| 测试/交付 | Demo数据、验收脚本、演示稳定性 |

若只有2-3人，优先保证：

```text

任务卡
任务中心
3个真执行Agent
飞书通知与回流
```

## 11. 每日演示脚本

每天结束前都要跑一次：

```text
1. 登录
2. 打开AI指挥台
3. 输入黄金Demo语句
4. 生成任务卡
5. 确认任务
6. 查看任务中心
7. 查看执行时间线
8. 查看结果或当天可用占位
```

Day 7增加：

```text
9. 飞书通知小张
10. 小张回复
11. 回复回流
12. 任务继续执行
13. 老板确认
14. 任务归档
```

## 12. Definition of Done

每个任务完成必须满足：

```text
有页面或API可验证
有最小测试或手动验收记录
错误状态可见
关键操作写入audit_logs或task_events
不破坏黄金Demo主链路
```

7天总验收：

```text
一条黄金Demo可完整演示
三套Demo数据可被检索
3个真执行Agent可输出结果
飞书通知和回复回流可用
轻量企业基座可支撑工作区、用户、角色、审计
```
