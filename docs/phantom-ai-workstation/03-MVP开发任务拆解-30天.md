# Phantom AI Workstation MVP 开发任务拆解（30天）

## 1. 团队配置假设

推荐最小团队：

| 角色 | 人数 | 主要职责 |
| --- | ---: | --- |
| 技术负责人/架构师 | 1 | 架构、接口、代码评审、集成把关 |
| 前端工程师 | 1 | Workbench UI、实时状态、任务页面 |
| 后端工程师 | 1 | FastAPI、数据库、权限、任务系统 |
| AI/RAG 工程师 | 1 | 文档解析、Embedding、Agent 执行、模型路由 |
| 测试/交付工程师 | 0.5-1 | 用例、演示数据、部署、验收 |

30 天按 4 周计算，建议预留 15%-20% 缓冲。若只有 2-3 人，MVP 范围必须砍掉会议中心或代码工厂中的一个。

## 2. MVP 范围

必须做：

- 登录与本地工作区
- 首页驾驶舱
- AI员工矩阵：CEO / COO / Sales / Bid / GEO / Code
- 文件上传、解析、切片、向量检索
- 带引用的知识库问答
- 任务中心：创建、执行、状态流、人工确认
- Agent 基础执行链路：规划、检索、生成、输出
- 招投标基础版：评分点提取、企业资料匹配、响应表
- 代码工厂基础版：需求输入、PRD 草案、技术拆解、代码草案 artifact
- 模型中心：本地模型配置与健康检查
- 审计日志
- Docker Compose 一键启动

暂不做：

- 多企业租户计费
- 高可用集群
- 复杂图谱可视化
- 全自动外发邮件
- 深度 CRM/ERP 集成
- 移动端 App

## 9. Definition of Done

每个功能完成必须满足：

- API 有请求/响应示例
- 数据库迁移已提交
- 前端有 loading/empty/error 状态
- 关键操作写审计日志
- Agent 输出能看到引用来源
- 异步任务失败时有错误信息和重试入口
- 至少一个单测或集成测试覆盖主要路径
- 演示环境可通过 `make demo-reset` 恢复

## 10. 30天最终验收脚本

### 场景 1：企业资料 AI 理解

```text
1. 登录 Phantom Workbench
2. 进入知识库
3. 上传企业介绍、产品手册、案例 PDF
4. 等待解析完成
5. 搜索“有哪些园区项目经验”
6. 查看返回片段、文档名、页码
```

通过标准：

- 文件状态从 uploaded 到 ready
- 检索结果包含至少 5 条相关 chunk
- 每条 chunk 有文档名与页码

### 场景 2：AI员工执行任务

```text
1. 进入任务中心
2. 创建“生成园区客户拜访方案”任务
3. 指派 Sales Agent
4. 实时查看 Agent 执行计划、检索、生成过程
5. 下载生成的方案文档
```

通过标准：

- 任务状态正确流转
- timeline 有 tool_call 和 model_call
- 输出内容带引用
- artifact 可下载

### 场景 3：招投标高价值 Demo

```text
1. 进入招投标中心
2. 上传招标文件
3. 点击分析
4. 查看评分点、风险点、企业资料匹配
5. 生成响应表
```

通过标准：

- 至少提取 10 个评分/响应要求
- 每个要求标记 matched/missing/risk
- matched 项有证据来源
- 响应表可下载

### 场景 4：代码工厂 Demo

```text
1. 进入代码工厂
2. 输入“做一个客户报价系统”
3. 生成 PRD
4. 生成技术拆解
5. 生成代码草案 artifact
```

通过标准：

- PRD 包含目标、角色、流程、功能列表
- 技术拆解包含数据模型、接口、页面
- 代码草案可以下载或预览

## 11. 主要风险与处理

| 风险 | 表现 | 处理 |
| --- | --- | --- |
| 本地模型效果不稳定 | 回答质量差、速度慢 | Demo 准备固定模型与固定样例；复杂任务允许云端模型开关 |
| 文档解析质量不稳定 | PDF 表格、扫描件失败 | MVP 优先支持文本 PDF/Office；扫描 OCR 作为增强项 |
| Agent 过度发散 | 输出不可控 | 使用结构化 schema、工具白名单、任务类型模板 |
| 前端实时状态复杂 | timeline 不一致 | 统一由 task_run 事件表驱动 UI |
| 30天范围过大 | 开发延期 | 优先保证知识库、任务、Agent、招投标四条主线 |
| 演示数据不足 | 看不出业务价值 | 第 2 周开始准备企业资料、招标文件、客户场景包 |

## 12. 建议开发顺序

```text
1. 先建仓库与 Docker Compose
2. 再建数据模型与 OpenAPI
3. 前端用 mock 并行搭页面
4. 后端先打通文件入库
5. AI/RAG 打通检索引用
6. Agent 只做 2 个真执行：Sales 和 Bid
7. 其余 Agent 先配置化展示
8. 最后补 Code Factory、Meeting、审计与模型中心
```

最小可演示版本只需要两个真 Agent：

- Sales Agent：客户方案与邮件
- Bid Agent：招投标解析与响应表

CEO、COO、GEO、Code 可以在第一版保持半自动或模板化，等核心闭环稳定后再增强。
